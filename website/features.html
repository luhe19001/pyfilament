Feature tour

Everything @task gives you.

pyfilament turns a plain async function into a durable, observable task. Every capability below is one keyword away — no boilerplate, no separate config.

The mental model

Decorate · call · await

Add @task to an async function. Calling it returns a run; awaiting the run executes it — with whatever reliability you asked for baked in.

tasks.pycopy
from filament import task

@task(tries=3, timeout=30, cache=True)
async def crunch(x):
    return await heavy(x)

run = crunch(42)        # calling a task returns a run
result = await run      # awaiting the run executes it

Reliability

Survive flaky reality
🔁

Retries with backoff

Re-run on failure with exponential backoff and jitter — no retry loop to write.

@task(tries=5, delay=1, backoff_base=2)
🎯

Selective retries

Retry only the errors worth retrying; fail fast on the ones that aren't.

retry_exceptions=[…], no_retry_exceptions=[…]
⏱️

Timeouts

Cap how long a run may take. Overruns are aborted and marked timeout.

@task(timeout=30)
💾

Result caching

Skip the body and reuse the stored result, with an optional TTL and forced refresh.

@task(cache=True, cache_ttl=3600)
🛑

Cancellation

Cancel a run cooperatively while it's in flight; children stop with it.

run.cancel()
🧹

Graceful shutdown

Signal a worker to drain its current work and exit cleanly — no dropped tasks.

serve(shutdown_event)

Flow control

Be a good citizen
🚦

Rate limiting

Cap executions per second across every worker, via a shared token bucket. Perfect for third-party APIs.

@task(rate_limit=5)
⚖️

Concurrency limits

Bound how many runs happen at once, using a distributed semaphore.

@task(max_concurrent=10)

Composition & scale

From one function to many workers
🌳

Subtasks & trees

Call tasks from inside tasks. Parent/child links are tracked so you can see the whole tree.

result = await child(x)
📡

Distributed queue & workers

Enqueue work to Redis and process it on any number of worker processes or machines.

await job.request(x) · await job.serve()

Observability

Tasks you can actually see
📈

State timeline

Every transition is recorded with timestamps — when it ran, retried, finished or failed.

created → running → success
📝

Structured logging

Per-run logs you can stream live in the dashboard. Just grab the task logger.

log = get_logger()
🔍

Args & result capture

Inputs and outputs are stored for inspection — and redactable when they're sensitive.

is_redact_input, is_redact_output
🖥️

Web dashboard

A FastAPI + GraphQL backend and a React UI to watch runs, trees and logs in real time.

uvicorn · GraphQL · React

Every run moves through a small, well-defined set of states:

createdrunningretrying successcached failuretimeoutcancelled

One decorator, everything on

The cheat sheet
cheatsheet.pycopy
@task(
    tries=5, delay=1, backoff_base=2,    # retry with backoff + jitter
    timeout=30,                          # abort slow runs
    cache=True, cache_ttl=3600,          # reuse results, expire after 1h
    rate_limit=5,                        # at most 5 / second, fleet-wide
    max_concurrent=10,                   # at most 10 in flight at once
    is_redact_input=True,                # keep sensitive args out of storage
)
async def crunch(x):
    return await heavy(x)

What you need

A small, standard stack

pyfilament is durable and observable by design, so it leans on a tiny bit of infrastructure. The tutorial gets you from zero to a running task — including the dashboard — in about ten minutes.

Python 3.14+The library targets the latest Python.
RedisPowers caching, queues, rate limits & locks. One Docker command.
A databaseSQLite by default (zero setup); Postgres for production.
